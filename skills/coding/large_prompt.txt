## 2. FULL DYNAMIC STRUCTURE — MANDATORY FOR ALL WEBSITES

All pages MUST be fully JS-driven. The HTML is a thin shell; all content is rendered by JavaScript. This is non-negotiable.

### 2.1 Architecture Pattern (always use this)
```
HTML Shell (static)          JS Data + Render Engine
─────────────────────        ──────────────────────────
<body>                       const APP_DATA = { ... }  ← ALL content lives here
  <div id="app">             function renderApp() { ... }  ← builds the DOM
  <!-- rendered by JS -->    function renderSection(key) { ... }
  </div>                     document.addEventListener('DOMContentLoaded', renderApp)
</body>
```

### 2.2 Dynamic Structure Rules
1. **Data Layer first**: declare all content as structured JS objects/arrays at the VERY TOP of `<script>` before any functions.
   ```js
   const SITE = {
     brand: { name: "...", tagline: "...", accent: "#..." },
     nav: [{ label: "Home", href: "#hero" }, ...],
     sections: [ { id: "...", type: "...", data: { ... } }, ... ],
     theme: { bg: "#...", card: "#...", border: "#...", text: "#..." }
   };
   ```
2. **Render engine**: write a `renderApp()` function that calls section-specific renderers and injects HTML into `#app`.
3. **Section types to render dynamically** (pick the ones relevant to the request):
   - `hero` — animated headline, subtitle, CTA buttons
   - `features` / `cards` — grid of glassmorphic cards with icons, titles, descriptions
   - `stats` — animated counter numbers (use `setInterval` + step increment)
   - `timeline` — vertical progress line with events
   - `quiz` / `interactive` — full state machine: `currentIndex`, `score`, `answers[]`
   - `table` / `list` — sortable/filterable JS-driven table or card list
   - `form` — validated form with real JS confirmation state, never a URL submit
   - `gallery` / `carousel` — JS-driven slides with prev/next/indicator controls
   - `pricing` — card grid with toggle (annual/monthly pricing swap)
   - `accordion` / `faq` — expand/collapse sections using `el.className =`
   - `modal` — overlay dialog opened by JS, closed by backdrop click or X button
   - `tabs` — tab bar with JS-driven panel switching
4. **State machine**: interactive apps (quiz, shop cart, wizard) must have a proper state object:
   ```js
   const STATE = { screen: 'home', step: 0, score: 0, cart: [], filters: {} };
   function setState(patch) { Object.assign(STATE, patch); rerender(); }
   ```
5. **Rerender loop**: when state changes, call a `rerender()` that replaces only the affected section's innerHTML — never full-page re-render.
6. **Event delegation at root**: bind ONE `document.addEventListener('click', ...)` (and one for `input`, one for `change` if needed). Use `event.target.closest('[data-action]')` to route actions. Never attach individual listeners inside render functions (they'd pile up on every rerender).
   ```js
   document.addEventListener('click', e => {
     const el = e.target.closest('[data-action]');
     if (!el) return;
     const action = el.dataset.action;
     const value = el.dataset.value || '';
     handleAction(action, value);
   });
   function handleAction(action, value) {
     if (action === 'start-quiz') setState({ screen: 'quiz', step: 0, score: 0 });
     else if (action === 'answer') handleAnswer(value);
     else if (action === 'open-modal') openModal(value);
     // ... etc
   }
   ```
7. **Animate counters**: for stats sections, animate numbers from 0 to their target using `setInterval`.
   ```js
   function animateCounter(el, target, duration = 1500) {
     let start = 0;
     const step = target / (duration / 16);
     const iv = setInterval(() => {
       start = Math.min(start + step, target);
       el.textContent = Math.floor(start).toLocaleString();
       if (start >= target) clearInterval(iv);
     }, 16);
   }
   ```
8. **Smooth section transitions**: when switching screens/steps, apply a CSS `@keyframes` fade or slide on the container using `el.style.animation = 'fadeIn 0.3s ease'`.

## 3. STYLE SYSTEM — MANDATORY

### 3.1 Design Token Object
Define a JS theme object at the top of your script and use it to inject CSS variables via JS:
```js
const THEME = {
  bg:        '#09090b',   // page background
  surface:   '#18181b',   // card/panel background
  border:    '#27272a',   // card border
  accent:    '#8b5cf6',   // primary accent color
  accent2:   '#06b6d4',   // secondary accent
  text:      '#fafafa',   // primary text
  muted:     '#a1a1aa',   // muted/secondary text
  radius:    '16px',      // card border radius
  font:      "'Inter', sans-serif",
};
// Inject as CSS variables for use in @keyframes and inline styles
document.documentElement.style.cssText = `
  --bg: ${THEME.bg}; --surface: ${THEME.surface}; --border: ${THEME.border};
  --accent: ${THEME.accent}; --accent2: ${THEME.accent2};
  --text: ${THEME.text}; --muted: ${THEME.muted};
`;
```
Use `style="background: var(--surface); border: 1px solid var(--border);"` on dynamically-rendered cards so the theme is applied consistently everywhere without re-specifying hex codes.

### 3.2 Glassmorphism Cards (required for ALL cards/panels)
Every card or panel MUST use:
- Background: semi-transparent surface with `backdrop-blur`
- Border: subtle 1px border with low-alpha accent
- Shadow: colored glow shadow on hover
```html
<div class="rounded-2xl p-6 lg:p-8 transition-all duration-300 hover:-translate-y-1"
     style="background: rgba(255,255,255,0.04); border: 1px solid rgba(255,255,255,0.08);
            backdrop-filter: blur(16px); box-shadow: 0 4px 24px rgba(0,0,0,0.3);">
```
On hover (via JS `data-action="hover"` or CSS group): add `box-shadow: 0 8px 32px rgba(VAR_ACCENT,0.2)`.

### 3.3 Typography Scale
Use these exact size patterns for hierarchy:
- Hero headline: `class="text-5xl md:text-7xl font-extrabold tracking-tight leading-none"`
- Section title: `class="text-3xl md:text-4xl font-bold tracking-tight"`
- Card title: `class="text-lg font-semibold"`
- Body: `class="text-sm md:text-base text-zinc-400 leading-relaxed"`
- Badge/label: `class="text-xs font-semibold uppercase tracking-widest"`

### 3.4 Gradient Text Headlines
Every hero headline MUST have a gradient-clipped text span:
```html
<h1 class="text-5xl md:text-7xl font-extrabold tracking-tight text-white">
  Regular words <span style="background: linear-gradient(135deg, var(--accent), var(--accent2));
    -webkit-background-clip: text; -webkit-text-fill-color: transparent; background-clip: text;">
    highlighted phrase
  </span>
</h1>
```

### 3.5 Buttons
Primary CTA:
```html
<button type="button" data-action="..."
  class="px-8 py-3.5 rounded-xl font-semibold text-white text-sm transition-all duration-300 hover:scale-105 hover:opacity-90"
  style="background: linear-gradient(135deg, var(--accent), var(--accent2));
         box-shadow: 0 4px 20px rgba(139,92,246,0.3);">
  Label
</button>
```
Secondary:
```html
<button type="button" data-action="..."
  class="px-8 py-3.5 rounded-xl font-semibold text-sm transition-all duration-300 hover:scale-105"
  style="background: transparent; border: 1px solid var(--border); color: var(--muted);">
  Label
</button>
```

### 3.6 Navigation Header
Fixed glassmorphic nav, always:
```html
<header class="fixed top-0 w-full z-50"
        style="background: rgba(9,9,11,0.8); backdrop-filter: blur(20px);
               border-bottom: 1px solid rgba(255,255,255,0.06);">
  <nav class="max-w-6xl mx-auto px-6 py-4 flex items-center justify-between">
    <!-- logo + links + CTA -->
  </nav>
</header>
<div class="pt-20"></div>  <!-- clearance for fixed nav -->
```

### 3.7 Background Decoration
Behind the hero, inject 2–3 blurred orbs for depth:
```html
<div class="fixed inset-0 pointer-events-none overflow-hidden" style="z-index:-1;">
  <div class="absolute rounded-full"
       style="width:600px;height:600px;top:-100px;left:-100px;
              background:radial-gradient(circle,rgba(139,92,246,0.12),transparent 70%);
              filter:blur(60px);"></div>
  <div class="absolute rounded-full"
       style="width:500px;height:500px;bottom:-50px;right:-50px;
              background:radial-gradient(circle,rgba(6,182,212,0.10),transparent 70%);
              filter:blur(60px);"></div>
</div>
```

### 3.8 Section Layout Wrapper (every section, no exceptions)
```html
<section id="unique-id" class="py-20 lg:py-28">
  <div class="max-w-6xl mx-auto px-6">
    <!-- content -->
  </div>
</section>
```
NEVER put content directly inside `<body>`, `<main>`, or bare `<section>` without a `max-w-* mx-auto px-6` centering wrapper.

### 3.9 Animations (@keyframes — in <style> block only)
Always include these base animations in your `<style>` block:
```css
@keyframes fadeInUp {
  from { opacity: 0; transform: translateY(24px); }
  to   { opacity: 1; transform: translateY(0); }
}
@keyframes fadeIn {
  from { opacity: 0; } to { opacity: 1; }
}
@keyframes glow {
  0%, 100% { box-shadow: 0 0 8px var(--accent); }
  50% { box-shadow: 0 0 24px var(--accent); }
}
@keyframes float {
  0%, 100% { transform: translateY(0); }
  50% { transform: translateY(-8px); }
}
@keyframes countUp {
  from { opacity: 0; transform: scale(0.8); }
  to   { opacity: 1; transform: scale(1); }
}
```
Apply entrance animations to rendered sections: `style="animation: fadeInUp 0.6s ease both;"` with `animation-delay` stagger on children.

### 3.10 Progress / Loading Bars
NEVER use `<progress>` or `<hr>`. Always use:
```html
<div class="w-full rounded-full overflow-hidden" style="background: rgba(255,255,255,0.08); height:6px;">
  <div id="bar-id" class="h-full rounded-full transition-all duration-500"
       style="width:0%; background: linear-gradient(90deg, var(--accent), var(--accent2));"></div>
</div>
```
Animate width with JS: `el.style.width = pct + '%'`.

## 5. TECHNICAL CORRECTNESS RULES — NON-NEGOTIABLE
1. **Object literals**: every property uses `:` not `=`.
2. **`<body>` text color**: always `text-white` (dark) or `text-zinc-900` (light).
3. **Every text-bearing element** gets its own explicit `text-*` class.
4. **Custom Tailwind colors**: if used, include `<script> tailwind.config = {...} </script>` in `<head>` with real hex values (if using Tailwind via CDN) or in `tailwind.config.js` (if using a build step).
5. **No `<style>` classes**: if using Tailwind, use it fully. For custom animations, use `@keyframes`.
6. **No scroll-reveal `opacity:0`**: use auto-playing `@keyframes` instead.
7. **No `classList.add/remove/toggle`**: if using vanilla JS, use `el.className = "full string"` or framework-specific state.
8. **No external image URLs**: CSS gradients, inline SVG, emoji, Lucide only.
9. **ID contract**: every `getElementById("x")` must have a matching `id="x"` in HTML.
10. **Close everything**: every string, template literal, tag, and bracket you open must close.
11. **Complete files**: Output complete, functional files. No truncation, no `<!-- TODO -->`.
12. **One currency symbol per price**: never `$$12.99`.
13. **Multi-file format**: You can output as many files as you need. For EACH file, use a separate markdown code block with the filename specified immediately after the language identifier, like this:
    ```html index.html
    <!DOCTYPE html>...
    ```
    ```css style.css
    body { ... }
    ```
14. **Event delegation at root**: if using vanilla JS, use single `document.addEventListener('click', ...)`, route by `data-action`. (Ignore if using React/Vue/etc.)
15. **Immediate render**: if using vanilla JS, call `renderApp()` or `initApp()` at bottom of script.
16. **Lucide icons**: use standard Lucide implementation for your chosen stack.
